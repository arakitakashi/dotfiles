# 完成の基準

「できた」と言う前に、ここを上から順に確かめる。機械で確かめられるものは機械に任せ、残りを目で見る。

## 1. 機械が確かめるもの

```bash
npm run check    # 検証 → 単体テスト → ビルド → 実ブラウザでの通し確認
```

| 段階 | 確かめていること |
|---|---|
| `validate` | レッスンの型（最初は準備か問題、解決の前に問題、最後は recap）、分量、用語の定義、リンク先、図の参照、物の重なり、指標の抜け、予測問題とつまみの整合、配色のコントラスト |
| `test` | エンジン・画面ロジック・検証規則が壊れていないこと |
| `build` | 型の誤りがなく、静的サイトとして出力できること |
| `smoke` | キーボードだけで全レッスンを完走できる、予測に答えるまで先へ進めない、完了と進捗が保存される、検索が開く、動きを減らす設定で動き続けるものがない、モバイルで図が貼り付き読める大きさで映る |

`validate` の **error は 0 件**にする。**warn は 1 件ずつ読み**、直すか、残す理由を説明できるようにする。
公開前は `npm run validate -- --strict` が通る状態を目指す。

## 2. 目で確かめるもの（撮影）

```bash
npm run capture -- --viewports desktop,mobile --themes light,dark --pages
```

全ステップの画像を開く。飛ばさない。図の出来は、データを読んでもわからない。

### 図

- [ ] 物・カード・ラベルが重なっていない。線が物を横切っていない
- [ ] 文字がすべて読める（ブロックの面からはみ出していない、ピルが切れていない）
- [ ] 前のステップと並べて、何が変わったかがひと目でわかる
- [ ] 変わっていない物は、前のステップと同じ位置にある
- [ ] `problem` のステップで、壊れていることが図だけで伝わる（赤い輪郭、止まった線、弾ける粒子、赤い指標）
- [ ] 同じ役割の物が、全レッスンで同じ色・同じアイコンになっている
- [ ] モバイルで、カメラが変化した部分を映している

### 文章

- [ ] 見出しだけを順に読んで、レッスンの筋がわかる
- [ ] どのステップも、本文の第 1 段落が「いま図で起きていること」を述べている
- [ ] 解説カードがスクロールなしで収まるステップが大半である（デスクトップ）
- [ ] 数値が、図の中（カード・ラベル）・本文・指標・差分リストで一致している
- [ ] 予測問題のあるステップで、回答前の画像（`-q.png`）の見出しや図が答えを明かしていない
- [ ] 比較表・要点・つまみ・予測問題が、潰れたり切れたりせずに表示されている

### 両テーマ

- [ ] ダークで読めない文字、沈んで見えない物がない
- [ ] アクセントの色が、現在地と主要な操作以外に使われていない

## 3. 内容の正しさ

機械にも撮影にも拾えない。**独立した目**で確かめる。

- [ ] 事実（数値、仕様、挙動、順序）を一次情報で確認した。確認した版や日付を控えている
- [ ] 予測問題の正解が本当に正しい。実際に動かして確かめられるものは動かした
- [ ] 単純化のために省いたことが、誤りになっていない（「常に」「必ず」と言い切った箇所を見直す）
- [ ] つまみの式が、現実の傾向と矛盾しない（方向と、閾値をまたぐ位置）
- [ ] フレッシュコンテキストのレビュアー（別のエージェント）に、題材の専門家として誤りを探させた

## 4. 学習体験

最初のレッスンを、初めての読者のつもりで最後まで通す。

- [ ] 開いた瞬間に、何をすればよいかわかる（次へのボタンと、その先の名前）
- [ ] 最初の 3 ステップで「なぜこれを学ぶのか」が体感できる
- [ ] 予測問題で、少し考え込む。簡単すぎず、当て推量にもならない
- [ ] つまみを動かすと、良くなる方向と悪くなる方向の両方がある
- [ ] recap を読んで、人に説明できる気がする
- [ ] 次のレッスンを読みたくなる問いで終わっている

## 5. 元にしたサイトの水準に対する確認

手本としたサイトが持っていた特徴と、欠けていた点。両方を満たして「同じ水準以上」になる。

### 持っていた特徴（維持する）

- [ ] 1 ステップ = 図の変化 1 つ。本文は 2 段落
- [ ] 図・本文・指標・差分リストが同じ変化を示す
- [ ] 問題が先、解決が後。解決策が次の問題を生む
- [ ] ステップの役割が色でわかり、タイムラインで起伏が読める
- [ ] 実際の事故（Case）と、誤解への予防（warn）がある
- [ ] 名前は体験の後
- [ ] 入口のページがなく、開けば続きから始まる。全ステップに URL がある
- [ ] キーボードだけで完走できる。検索がステップ単位で当たる

### 欠けていた点（この雛形で補っている。内容で活かす）

- [ ] 予測問題が各レッスンにある
- [ ] つまみで動かせるステップが、トレードオフのある箇所にある
- [ ] レッスン間の参照がリンクになっている
- [ ] チートシートと用語集が中身を持っている（recap の要点と用語の定義を書いた）
- [ ] モバイルで図が読め、読み進めても見えている
- [ ] 動きを減らす設定で、すべての動きが止まる
- [ ] 図に代替テキストがある。現在地が支援技術に伝わる
- [ ] 補助の文字色まで 4.5:1 以上ある

## 6. 引き渡し

- [ ] `npm run check` が通る
- [ ] `npm run dev` で開いて、最初のレッスンを自分で最後まで進めた
- [ ] 起動方法（`npm install` → `npm run dev`）、公開方法（`npm run build` → `dist/` を置く）、レッスンの足し方を伝えた
- [ ] 確認できなかったこと、単純化したこと、今後足すとよいレッスンを伝えた
