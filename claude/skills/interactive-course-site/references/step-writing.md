# ステップの書き方

1 ステップは、図を見ながら 30 秒以内で読める量にする。読者の目は図と文章を往復するので、文章が長いと図の変化を見逃す。

## 分量の基準

| 項目 | 日本語 | 英語など |
|---|---|---|
| 本文 | 2 段落。1 段落 40〜120 字、合計 270 字以内 | 2 段落。1 段落 30 語前後、合計 110 語以内 |
| 見出し（`title`） | 1 行に収まる長さ（全角 22 字程度まで） | 8 語程度まで |
| タイムラインの名前（`short`） | 全角 9 字まで | 3 語まで |
| callout | 1〜2 文、110 字以内 | 40 語以内 |
| 差分（`changes`） | 1〜3 行 | 同左 |
| 代替テキスト（`alt`） | 1〜2 文 | 同左 |

これは書くときの目安。`npm run validate` の警告は少し緩く、日本語では 1 段落 20 字未満・150 字超、合計 270 字超、`short` 9 字超、callout 110 字超で出る。
超えたら、文章を削るのではなくステップを分けることを先に考える。

## 本文は 2 拍子

- **第 1 段落: いま図で起きていること。** 状況、操作、数値。「〜を追加しました」「〜が 3 秒かかります」
- **第 2 段落: その帰結か、理由。** 「だから〜です」「〜だけです」。短い断定で締める

```
一覧を並べ替える `sortRows()` を追加しました。10 万行あり、終わるまで **3 秒** かかります。
そのあいだ、メインスレッドはこの関数にかかりきりです。

クリックしても反応がなく、スクロールも止まります。壊れたわけではありません。
先に始めた仕事が終わるまで、次の仕事に手を付けられないだけです。
```

### 語り口

- 現在形、短文、実況。読者に話しかけるが、問いかけを連発しない
- 具体から入る。「サーバー B の負荷は 97%」が先で、「偏りが生じる」は後
- 数値を必ず入れる。「遅くなる」ではなく「4 ms が 3,000 ms になる」
- 1 ステップの新出用語は 1〜2 個まで。`==用語==` で印を付け、その文の中で意味がわかるように書く
- 実在の製品名・規格名は本文の流れに入れず、callout（`tip`）に寄せる

## 見出しは「状況・問い・命令」

名詞の定義にしない。見出しだけを追って、レッスンの筋がわかるのが理想。

| 悪い | 良い |
|---|---|
| ロードバランサーとは | 3 台のサーバーに、入口は 1 つ |
| キャッシュの無効化 | 値段を変えたのに、古い値段が出る |
| ヘルスチェック | 倒れたサーバーに、まだ送っている |
| マイクロタスク | Promise は列に割り込む |
| まとめ | 1 本のスレッドを、空けておく |

前のステップから続ける見出し（「…そして、それ自体が単一障害点になる」）も使える。

## callout の 4 種

1 ステップに 1 つ。本文の具体を、1 文で抽象に持ち上げる場所。

| kind | 中身 | 例 |
|---|---|---|
| `insight` | このステップの教訓を 1 文で | 「順番に振り分ける方式は、相手の忙しさを知らない」 |
| `warn` | 誤解・落とし穴の予防。俗説を名指しで否定する | 「`await` を入れたから固まらない、は誤解です」 |
| `tip` | 実在の製品・規格・経験則。本文の話を現実に接地させる | 「目安は 50 ms 以内。これを超える仕事はロングタスクと呼ばれます」 |
| `next` | recap 専用。次のレッスンへの問い | 「その 155 ms は、数千人が同時に来たらどうなるか」 |

`warn` は誤解への予防接種として最も効く。読者が持ち込みそうな思い込みを 1 レッスンに 2〜3 個見つけ、名指しで否定する。

## 差分リスト（changes）

前のステップから図で何が変わったかを、git の差分のように書く。

```
+ Web API（タイマー）
- スタックに居座る処理
~ フレーム時間 3,000 ms → 5 ms
```

- `+` 追加、`-` 削除、`~` 変更。記号の後に半角スペース
- 数値の変化は「前 → 後」で書く
- 図の差分と一致させる。図に物が増えたら `+` の行があるはず

## 代替テキスト（alt）

図が見えない読者に、そのステップの状態を伝える。「〜の図」ではなく、**何がどうなっているか**を書く。

- 悪い: 「イベントループの図」
- 良い: 「コールスタックに sortRows が積まれ、タスクキューにクリックが 3 件並んで待っている」

## recap の要点（takeaways）

- 4〜5 個。それぞれ 1 文
- キーワードを太字にする
- チートシートに単独で載るので、レッスンを読んでいない人にも意味が通るように書く
- 「〜を学んだ」ではなく、事実として書く（「マイクロタスクはタスクより先に、空になるまで実行される」）

## 記法

本文・callout・要点・表・予測問題で使える。生の HTML は書けない（すべて無害化される）。

| 記法 | 表示 |
|---|---|
| `**太字**` | 数値・キーワードの強調 |
| `==用語==` | 新出用語。蛍光ペンの下線が付き、用語集へリンクする。`Course.glossary` に定義が必要 |
| `` `code` `` | 識別子・コマンド |
| `*強調*` | 他のレッスンの名前など |
| `[[lesson-id#3\|文]]` | レッスンのステップへのリンク。`#3` を省くと先頭 |

## よくある失敗

| 失敗 | 直し方 |
|---|---|
| 1 ステップで 2 つのことを説明している | 分ける。迷ったら分ける |
| 本文が図の説明になっていない（図と無関係な一般論） | 第 1 段落を「いま図で起きていること」に書き直す |
| 解決策を先に出してしまう | 直前に、それがない場合に壊れるステップを足す |
| 用語の定義から始まる | 現象を先に見せ、名前は後のステップで出す |
| 数値がない | 指標の値を本文にも書く |
| callout が本文の繰り返し | 1 段上の抽象か、落とし穴か、実例のどれかに変える |
| 「重要です」「注目してください」などの空句 | 削る。何がどう重要かを数値で示す |
