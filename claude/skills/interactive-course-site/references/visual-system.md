# ビジュアルの体系

雛形の見た目は、少数の規則を全体に一貫して適用することで成り立っている。
部品を足したり色を変えたりするときは、新しい表現を持ち込む前に、既存の規則で表せないかを先に考える。

## 1. 方向性

「紙の上に置かれた、手で触れそうな計器盤」。
情報の密度を恐れず、1 画面に目次・図・解説・進捗を収める。余白で上品に見せる方向ではなく、整理された密度で信頼を得る方向。

ありがちな学習サイト（白い背景、青いアクセント、ぼかした影、長い文章の列）との違いは、次の 5 つの規則から生まれる。

## 2. テーマの選び方

`Course.theme` で選ぶ。どれもライトとダークがあり、OS の設定に従い、手動の切り替えを記憶する。

| テーマ | 地の色 | アクセント | 向いている題材 |
|---|---|---|---|
| `paper` | 生成りの紙 | マリーゴールド | Web・プログラミング入門、手を動かす題材、親しみやすさが要るもの |
| `slate` | 冷たい灰 | ミント | インフラ、ネットワーク、計測、運用。冷静さ・精密さが要るもの |
| `studio` | 中立の灰白 | コーラル | 言語処理系、アルゴリズム、数理、デザイン。抽象度の高いもの |

題材の印象に合うものがなければ、9 節の手順で新しく作る。既存のテーマの色を数か所だけ変えるのは避ける（色温度がばらつく）。

## 3. 規則 1: 影は 2 系統、意味で使い分ける

| 系統 | 見た目 | 付ける対象 | トークン |
|---|---|---|---|
| **ポップ** | ぼかしのない、ずれた ink の影 | 押せるもの、現在地、最前面のもの | `--pop`（2px 3px）、`--pop-sm`（0 2px） |
| **ソフト** | 上端の白い光 + 下方向だけの淡い影 | 面、カード、容器 | `--soft`、`--soft-lg` |

- ボタン・タグ・バッジ・選択中の項目・図の中のピルとカードはポップ
- 解説カード・タイムライン・目標のカードはソフト
- 押すと影が消えて 2px 沈む（`:active`）。物理的なボタンの手応え
- ソフトの影の色は黒ではなく、テーマの `--shade`（地の色と同じ色温度）

1 つの要素に両方を付けない。どこにでも同じ影を付けると、「押せる」という合図が消える。

## 4. 規則 2: 輪郭は ink

- 操作できる要素と、図の中の物は、1.5px 前後の `--ink` の輪郭を持つ
- 面の区切りは 1px の `--line`（ほとんど見えない程度）。面同士は線ではなく、地の色の差とソフトの影で分ける
- 現在地でない項目にも透明の輪郭を置いておき、選ばれてもレイアウトがずれないようにする
- 図の中の文字は、床や線の上に直接置かず、必ずピルに載せる（`pill()`）

UI のボタンと、図の中のピルやカードが同じ語彙（ink の輪郭 + ずれた影）で描かれているので、画面全体が 1 つの物に見える。

## 5. 規則 3: 色は役割で決まる

色には 3 つの層がある。

| 層 | 用途 | トークン |
|---|---|---|
| 地 | 背景と面。3 段階の明るさ | `--bg` < `--surface` < `--card` < `--raised` |
| 文字 | 4 段階。すべて card の上で 4.5:1 以上 | `--ink` `--ink-2` `--muted` `--muted-2` |
| 役割色 | 図のブロック・粒子・バッジ・コールアウトで共有する 9 色 | `--h-<hue>-top / -side / -side2 / -line / -ink / -pk / -tile` |

- アクセント（`--accent`）は「現在地」と「主要な操作」だけに使う。飾りに使わない
- 状態色（`--good` `--warn` `--bad`）は指標と差分にだけ使う
- ステップの役割（chapter）にも色が割り当てられている: 準備 = sand、問題 = red、解決 = green、しくみ = blue、トレードオフ = amber、洞察 = violet、まとめ = ink
- 彩度の高い色は小さな面積（粒子、目次の点）にだけ使う。大きな面は淡い色（`-top`、`-tile`）
- ダークテーマは、同じトークンの値を差し替えるだけで成立する。図も CSS 変数で色を引いているので、追加の処理は要らない

## 6. 規則 4: 書体は 2 つ、階層は太さで作る

| 用途 | 書体 | トークン |
|---|---|---|
| 見出し・本文・画面の文言 | IBM Plex Sans JP | `--font` |
| 数値・コード・キー表記・番号 | IBM Plex Mono | `--mono` |

| 役割 | 大きさ | 太さ |
|---|---|---|
| レッスンのタイトル | `--fs-title`（22〜28px） | 700 |
| ステップの見出し | `--fs-h2`（19px） | 700 |
| 本文 | `--fs-body`（15px）、行送り 1.8 | 400 |
| 画面の文言 | `--fs-ui`（14px） | 400 / 500 / 700 |
| 補助 | `--fs-small`（13px）、`--fs-micro`（12px） | — |

- 大きさの段を増やさない。差は太さ（400 / 500 / 700）と色（ink / muted）で付ける
- 数値は等幅にして `tabular-nums` を効かせる（数え上げのアニメーションで桁が揺れない）
- 本文は 15px を下回らせない。図の中の文字は、画面上で 9px 相当を下回るとカメラが自動で寄る
- 和文を含むフォントを明示しているので、OS によって見え方が大きく変わらない

## 7. 規則 5: モーションは語彙から選ぶ

時間とイージングは決まった値だけを使う。場当たりの `transition: all .3s` を足さない。

### 図（`src/engine/tween.ts`）

| 段階 | 時間 | イージング |
|---|---|---|
| 退場 | 380 ms | inOut |
| 移動・カメラ | 760 ms | inOut |
| 登場（110 ms ずつずらす） | 620 ms | back（少し行き過ぎて戻る） |
| 線を引く | 520 ms | inOut |
| 数値の数え上げ | 700 ms | out |

順序は必ず「退場 → 移動 → 登場 → 線 → 粒子」。消えるものが先に消え、残るものが動き、新しいものが現れ、最後に関係が結ばれる。

### 画面（`src/styles/tokens.css`）

| トークン | 値 | 用途 |
|---|---|---|
| `--e-out` | `cubic-bezier(.2,.7,.2,1)` | ほぼすべて。素早く出て、やわらかく止まる |
| `--e-spring` | `cubic-bezier(.34,1.5,.64,1)` | チェックが付く、点が選ばれる、などの小さな喜び |
| `--d-fast` | 140 ms | ホバー、押下 |
| `--d-ui` | 320 ms | 開閉、内容の入れ替え |

- 解説の内容は、進む方向から滑り込む（次へなら右から、戻るなら左から）
- 指標が変わると、チップが一瞬浮いて光る
- `prefers-reduced-motion` では、図の振り付け・粒子・CSS のアニメーションをすべて止め、粒子は経路上の静止した印として残す

## 8. レイアウト

| 幅 | 構成 |
|---|---|
| 1240px 以上 | 3 ペイン: 目次 272px / 図（残り）/ 解説 400px。画面は縦にスクロールしない |
| 900〜1239px | 2 ペイン: 図 / 解説。目次は引き出し |
| 899px 以下（または高さ 599px 以下） | 縦積み。図が画面上部に貼り付き、解説を読み進めても見えたまま。前へ・次へは画面下に固定 |

- 図が主、文章が従。中央の最大面積を図に与える
- 解説の 1 行は全角 22〜26 字。短い行で、図と往復しながら読める
- 前へ・次へのボタンは常に同じ位置。次へのラベルには次のステップ名を入れる

## 9. 新しいテーマを作る

`src/styles/themes.css` のテーマのブロックを 1 組（ライトとダーク）複製し、`data-palette` の名前と値を変える。`src/types.ts` の `Course.theme` の型にも名前を足す。

1. **地の色を決める。** 純白にしない。わずかに色を帯びた明るい色を `--card` とし、そこから 2〜3% ずつ暗くして `--surface`、`--bg` を作る
2. **ink を決める。** 純黒にしない。地と同じ色相に寄せた、ほぼ黒
3. **`--shade` を地と同じ色温度にする。** 影が黒く浮かない
4. **アクセントを 1 色決める。** 明るく彩度のある色。その上に ink の文字が 4.5:1 以上で載ること
5. **ダークは、地を「色を帯びた暗色」にする。** 青黒や純黒ではなく、ライトと同じ色相の暗色
6. `npm run validate` でコントラストを検査し、`npm run capture -- --themes light,dark` で両方を見る

役割色（`--h-*`）は全テーマ共通なので、変えなくてよい。

## 10. 書体を替える

1. `@fontsource/<書体>` を入れる（和文を含む題材は、和文の字形を持つ書体を選ぶ）
2. `src/styles/fonts.css` の `@import` を差し替える
3. `src/styles/tokens.css` の `--font` と `--mono` の先頭を替える

2 書体を超えない。見出しだけ別の書体にする、という足し方はしない。

## 11. やってはいけないこと

| 行為 | 理由 |
|---|---|
| 純白の背景、純黒の文字や影 | 色温度がそろわず、紙の質感が消える |
| ぼかした影をボタンに、ポップの影をカードに付ける | 「押せる」の合図が壊れる |
| 飾りのためのグラデーション、絵文字、装飾のイラスト | 図の記号体系と競合する |
| 図の中に色コードを直接書く | ダークテーマで破綻する |
| レッスンごとに役割の色を変える | 記号体系が崩れ、読者が色を覚え直すことになる |
| 語彙にない時間やイージングを足す | 画面全体の動きのリズムがばらつく |
| 3 つ目の書体、新しい文字サイズ | 階層が読めなくなる |
| 図の文字を床や線の上に直接置く | 読めない。必ずピルに載せる |
